# 🐱 Шишка-бот Telegram

<p align="center">
  <img src="assets/shishka_logo.png" alt="Шишка" width="220">
</p>

Простой, но эффективный **автоматический модератор для Telegram**.
С репортами, логами, фильтром мата, ИИ для анти-спама, обнаружением NSFW, системой репутации и не только :3

---

## Что умеет Шишка-бот?

- **Анти-спам**: ML-детекция спама от новых пользователей, с allow-листом для заведомо безопасных доменов (например, YouTube), чтобы не резать обычные ссылки на видео
- **Доверенные пользователи**: участники с достаточной репутацией *или* достаточным числом сообщений не проходят повторные автоматические проверки модерации — это защищает уже давно активных людей от ложных срабатываний
- **NSFW-детекция**: проверка фото в чате и аватаров
- **Система репутации**: пользователи получают репутацию за активность
- **Система репортов**: пользователи могут жаловаться на сообщения админам
- **Плановые объявления**: периодические автоматические сообщения
- **Анти-бот**: автоматическое удаление ботов без прав администратора (с белым списком)
- **Система фото кошек**: случайные фото Шишки с возможностью загрузки админами 🐱
- **Шиш-таро**: одна случайная Шишка закрепляется за пользователем на текущий день
- **Эфемерные ответы**: `/rules`, `/help` и `/me` сами удаляются из чата через некоторое время, не засоряя историю
- **Резервное копирование**: скрипт `scripts/backup_db.sh` бэкапит базу с сервера на ноутбук по SSH, а `!backup_now`/автопланировщик отправляют бэкап прямо в Telegram — без сервера и SSH-ключей вообще 🆕
- **Топ по репутации**: `!top` показывает лидерборд участников чата 🆕
- **Друзья Шишки**: отдельная категория фото для чужих котиков (`/add_shis_friend`), плюс очередь модерации `!submit_shishka`/`!submit_shis_friend` — предлагать фото может любой пользователь 🆕
- **Антирейд**: массовый одновременный вход новых участников автоматически включает временное ограничение на отправку сообщений, пока админы не разберутся 🆕
- **Лестница предупреждений**: `!warn` копит предупреждения и сам эскалирует до мута и бана по настраиваемым порогам 🆕
- **Метрики**: лёгкий JSON-эндпоинт `/metrics` на встроенном healthcheck-сервере — сколько сообщений, банов, спама, предупреждений и т.д. 🆕

## 🆕 Что нового в этой версии

### 💾 Резервное копирование базы данных

Одной командой с вашего ноутбука (бот **не нужно останавливать** — используется безопасное «горячее» копирование):

```bash
./scripts/backup_db.sh -H server.example.com -u deploy
```

Скрипт сам заходит на сервер по SSH, определяет тип базы (SQLite / PostgreSQL / MySQL) по `DB_URL` из `.env`/`config.toml`, снимает консистентный снапшот, скачивает его к вам и подчищает временные файлы на сервере. Есть ротация старых бэкапов и удобный `--help`.

Подробности и параметры — см. [«Резервное копирование»](#-резервное-копирование) ниже.

### 👻 Эфемерные сообщения

`/rules`, `/help` (в том числе кнопки «📋 Правила» / «🐱 Ещё Шишку!» и естественный вызов вроде «шишка, помоги») и `/me` теперь **автоматически удаляются** через настраиваемое время, а вызвавшая их команда стирается сразу — чат не захламляется перепиской с ботом. Настраивается в `config.toml` в секции `[ephemeral]`, подробнее — [ниже](#-эфемерные-сообщения-1).

### 🛡️ Анти-спам без лишних блокировок

Исправлены две конкретные проблемы с ложными срабатываниями:

- **Ссылки с YouTube и других безопасных площадок** больше не удаляются наравне со спам-ссылками — добавлен настраиваемый allow-лист доменов (`spam.link_domain_allowlist`), который проверяет *настоящий* адрес ссылки (а не текст), так что подмену не обмануть.
- **Уже активные участники** больше не попадают под полную модерацию из-за случайного проседания репутации (например, из-за одного штрафа за голосовое сообщение) — теперь исключение из проверок работает и по количеству сообщений (`cache.trusted_user_messages`), а не только по репутации.

Полный список идей на будущее — в разделе [«Анти-спам и анти-бот: что дальше»](#️-анти-спам-и-анти-бот-что-дальше).

### 🐱 Команда `шишка`

Любой пользователь может получить случайное фото кошки из базы:

| Команда | Описание |
|---------|----------|
| `шишка` / `shishka` / `кошка` / `cat` | Случайное фото кошки 🐱 |
| `/add_shishka` | Добавить фото (ответом на фото) — админы |
| `/del_shishka <ID>` | Удалить фото по ID — админы |
| `/list_shishka` | Список всех фото — админы |
| `/shish_tarot` / «что у меня сегодня шишка» | Получить Шишку дня |
| `/help` / «шишка хэлп» / «шишка помоги» | Показать справку (эфемерно) |

### 🛡️ Белый список ботов

Боты из белого списка **никогда не удаляются**, даже без прав администратора.

Настройка в `.env`:

```env
BOT_WHITELIST=123456789,987654321
```

### 👋 Приветствия с Шишкой

При входе нового пользователя:

1. Удаляется служебное сообщение о вступлении.
2. Отправляется случайное приветствие с упоминанием Шишки.
3. Если в базе есть фото — отправляется случайное фото.
4. Показываются кнопки: 📋 Правила и 🐱 Ещё Шишку!

## 🆕 Новое в этом обновлении (v1.2.0)

### 💌 Бэкапы прямо в Telegram

Помимо `scripts/backup_db.sh` (SSH-пуллинг на ноутбук), бот теперь умеет бэкапиться сам себе: `!backup_now` (владелец) снимает безопасный снапшот базы (SQLite `.backup()`, работает на живой базе без остановки бота) и присылает его документом в текущий чат. Автоматическая ночная отправка включается в `config.toml` секцией `[backup]` — тогда бэкап улетает владельцу в личку по расписанию без какой-либо инфраструктуры. Подробнее — [ниже](#-резервное-копирование).

### 🏆 `!top` — топ по репутации

Любой участник может посмотреть лидерборд чата: `!top` или `!top 20`.

### 🐾 Друзья Шишки + очередь модерации

Раньше фото мог добавлять только админ командой `/add_shishka`. Теперь:

- `/add_shis_friend` — админ добавляет фото **чужого** кота в отдельную категорию (не смешивается со случайной выдачей «шишка»);
- `/shis_friends` — показать случайное фото кота-друга;
- `!submit_shishka` / `!submit_shis_friend` — **любой** пользователь может предложить своё фото ответом на него; заявка улетает в чат репортов/логов с кнопками ✅ «Одобрить» / ❌ «Отклонить», и попадает в базу только после решения админа.

### 🛡️ Антирейд

Если в чат за короткое время (по умолчанию 5 человек за 30 секунд, `[raid_guard]` в config.toml) вступает подозрительно много новых участников — это, скорее всего, скоординированный спам-рейд, а не органический рост. Бот временно переводит новичков в режим «только чтение» (по умолчанию на час) вместо обычной проверки «напиши сообщение или тебя удалят» (которая в разгар рейда несправедливо задевала бы и настоящих людей), и один раз пишет админам в лог-чат. Снять ограничение раньше срока — `!raid_off`.

### ⚠️ Лестница предупреждений

`!warn [причина]` (ответом на сообщение, админ) — формальное предупреждение, в отличие от автоматических списаний репутации: видимое, накопительное, с прозрачной эскалацией. Пороги настраиваются в `[warn]`:

| Предупреждений | Последствие (по умолчанию) |
|---|---|
| 2 | мут на 1 час |
| 3 | мут на 1 день |
| 4 | бан |

`!warns` — проверить количество предупреждений (свои — без ответа, чужие — ответом на сообщение). `!unwarn` — снять последнее предупреждение. `!clearwarns` — сбросить все.

### 📊 Метрики

Если включён healthcheck-сервер (`[healthcheck] enabled = true`), на `/metrics` доступна лёгкая JSON-сводка: аптайм и счётчики (сообщения, разные виды удалённого спама, автобаны, NSFW-находки, рейды, предупреждения, добавленные фото котиков). Без внешних зависимостей вроде Prometheus — просто JSON, который легко забрать скриптом или дашбордом.

Тот же снимок доступен и прямо в чате: `!metrics` / `/metrics` (владелец бота) присылает те же счётчики текстом, без захода на сервер.

## 💾 Резервное копирование

База данных бота (SQLite по умолчанию, но поддерживаются и PostgreSQL/MySQL через `DB_URL`) живёт на сервере. Скрипт `scripts/backup_db.sh` запускается **на вашем ноутбуке** и скачивает свежую копию к вам, ничего не требуя от сервера, кроме обычного SSH-доступа.

```bash
# минимум - хост и пользователь
./scripts/backup_db.sh -H 203.0.113.10 -u root

# с ключом, нестандартным путём и своей папкой для бэкапов
./scripts/backup_db.sh -H bot.mydomain.com -u deploy \
    -i ~/.ssh/id_ed25519 -d /opt/shishka_bot -o ~/shishka-backups -k 30
```

Как это работает:

1. Скрипт подключается по SSH и читает `DB_URL` из `.env` (или `config.toml`) в каталоге бота на сервере.
2. Для SQLite используется команда `sqlite3 ... ".backup"` — это официальный безопасный способ снять копию БД, даже пока бот работает и пишет в неё. Для PostgreSQL/MySQL используются `pg_dump`/`mysqldump`.
3. Готовый снапшот сжимается, скачивается к вам через `scp` и стирается с сервера.
4. Локально хранится ограниченное число последних бэкапов (`--keep`, по умолчанию 14).

Все параметры — `./scripts/backup_db.sh --help`.

Восстановление:

- **SQLite** — остановите бота, замените файл базы (тот, что указан в `DB_URL`) на распакованный `*.sqlite3` из бэкапа, запустите бота снова.
- **PostgreSQL/MySQL** — распакуйте `*.sql.gz` и примените через `psql`/`mysql` к (пустой) целевой базе.

Хотите бэкапы по расписанию — добавьте вызов скрипта в `cron` на своём ноутбуке или домашнем сервере (пример есть в самом скрипте).

### Альтернатива: бэкап прямо в Telegram (без SSH)

Если доступа к серверу по SSH нет (или просто лень его настраивать), бот может бэкапиться сам:

```
!backup_now
```

Владелец бота (`[bot] owner`) запускает эту команду в любом чате с ботом — бот снимет тот же безопасный снапшот (тем же методом, что и `backup_db.sh` — `sqlite3`-совместимый `.backup()`, безопасно на живой базе) прямо в процессе, сожмёт его и пришлёт файлом в этот же чат.

Автоматическая отправка по расписанию — в `config.toml`:

```toml
[backup]
enabled = true       # включить автоматические бэкапы
chat_id = 0          # 0 = отправлять владельцу в личку; либо укажите ID нужного чата
interval_hours = 24  # как часто
```

Никакой дополнительной инфраструктуры не требуется — только сам бот и его обычный токен.

## 👻 Эфемерные сообщения

Настраивается в `config.toml`:

```toml
[ephemeral]
enabled = true          # включить/выключить всю фичу
delete_trigger = true   # удалять саму команду (!rules/!help/!me) в группах
help_ttl = 45           # сек. до самоудаления ответа на /help
rules_ttl = 60          # сек. до самоудаления ответа на /rules
stats_ttl = 30          # сек. до самоудаления ответа на /me
```

Поведение:

- Работает только в группах/супергруппах — в личных сообщениях с ботом ничего не удаляется (незачем).
- Ответ бота (текст, правила, справка со случайной Шишкой) удаляется через `*_ttl` секунд.
- Сама команда пользователя удаляется сразу после ответа, если `delete_trigger = true`.
- Кнопки «📋 Правила» и «🐱 Ещё Шишку!» тоже отправляют эфемерные ответы.

## Интернационализация (i18n)

Бот использует [Project Fluent](https://projectfluent.org/) для переводов.

Использование в обработчиках:

```python
# Способ 1: импорт функции _ напрямую
from core.i18n import _

async def handler(message: Message) -> None:
    text = _("error-no-reply")
    await message.reply(text)

# Способ 2: использование i18n из мидлвари (локаль пользователя)
async def handler(message: Message, i18n: Callable) -> None:
    text = i18n("error-no-reply")
    await message.reply(text)

# С переменными
text = _("report-message", date="2024-01-01", chat_id="123", msg_id="456")
```

Добавление новых переводов:

1. Создайте/отредактируйте `.ftl` файлы в `locales/{lang}/`.
2. Используйте ключи через дефис: `error-no-reply`.
3. Переменные используют синтаксис `{ $var }`.

Пример `locales/ru/strings.ftl`:

```fluent
error-no-reply = Эта команда должна быть ответом на сообщение!
report-message = 👆 Отправлено { $date }
    <a href="https://t.me/c/{ $chat_id }/{ $msg_id }">Перейти</a>

# Приветствия с Шишкой 🐱
welcome-v1 = 👋 { $username }, добро пожаловать! 🐱 Наша кошка Шишка уже ждёт новых друзей! 🎉
```

## Установка

### Требования

- Python 3.11+
- Токен бота от [@BotFather](https://t.me/BotFather)
- ~4 ГБ свободного места для ML моделей

### Процесс установки

1. Клонируйте репозиторий:

    ```bash
    git clone https://github.com/Luno-o/shishka_bot.git
    cd shishka_bot
    ```

2. Создайте виртуальное окружение:

    ```bash
    python -m venv venv
    source venv/bin/activate  # Linux/Mac
    venv\Scripts\activate     # Windows
    ```

3. Установите зависимости:

    ```bash
    pip install -r requirements.txt
    ```

4. Скопируйте `.env.example` в `.env` и заполните значения:

    ```bash
    cp .env.example .env
    ```

5. Настройте `config.toml` под свои нужды.

6. Скачайте ML-модели (они НЕ включены в репозиторий):

    ```bash
    python download_model.py      # Спам-модель (~328 MB)
    python nsfwmodel_down.py      # NSFW-модель
    ```

    База данных и все миграции применяются автоматически при запуске бота.

7. Запустите бота:

    ```bash
    python bot.py
    ```

### Переменные окружения в продакшене

```bash
# Экспорт переменных напрямую
export BOT_TOKEN="your_bot_token"
```

### Использование RAM

В данный момент бот использует ~800 МБ RAM для ML-моделей и кэширования данных. Квантование моделей — единственное найденное жизнеспособное решение для дальнейшего снижения потребления памяти; переход на ONNX runtime не дал результата.

Если ваш сервер не справляется и процесс убивается с ошибкой Out of memory — простое решение — добавить swap:

```bash
# Создать swap файл на 2 ГБ
fallocate -l 2G /swapfile
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile

# Сделать постоянным
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

## 🛡️ Анти-спам и анти-бот: что дальше

Уже реализовано:

- allow-лист доменов для ссылок (`spam.link_domain_allowlist`, по умолчанию YouTube), защищённый от подмены — сравнивается настоящий адрес ссылки, а не отображаемый текст;
- исключение из модерации по накопленной активности (`cache.trusted_user_messages`), а не только по репутации, чтобы разовый штраф не превращал давнего участника в «нового»;
- **антирейд по всплеску вступлений** (`[raid_guard]`) — не совсем то же самое, что анти-флуд по сообщениям (идея №6 ниже), но решает соседнюю и более острую проблему: скоординированный массовый вход спам-аккаунтов;
- **формальные предупреждения с эскалацией** (`!warn`, `[warn]`) — прозрачная, накопительная альтернатива автоматическим списаниям репутации.

Идеи на будущее (не реализованы, требуют обсуждения перед внедрением):

1. **Проверка по внешним базам спам-ботов** (например, по типу [CAS/Combot Anti-Spam](https://cas.chat/)) прямо при входе — банить заведомо известных спам-ботов ещё до первого сообщения.
2. **Эвристика по возрасту аккаунта**: числовой Telegram ID грубо коррелирует с датой регистрации аккаунта — дешёвый дополнительный сигнал для очень новых аккаунтов, без необходимости в ML.
3. **«Карантин» для новичков** отдельно от полного исключения из модерации: ограничить медиа/ссылки/форварды на первые N сообщений, но не задерживать обычный текстовый чат — сейчас это одна из причин ложных блокировок у новых, но живых людей.
4. **Изменение allow/deny-листа доменов прямо из чата** (`!linkallow`/`!linkdeny`) без правки `config.toml` и рестарта бота.
5. **`/trust @user`** — команда админа, чтобы вручную снять с конкретного пользователя ограничения (быстрое ручное исправление ложного срабатывания).
6. **Анти-флуд по скорости для отдельного пользователя** (например, >5 сообщений за 5 секунд) как независимый от ML сигнал бот-подобного поведения — дополнит уже реализованный антирейд, который смотрит на *вступления*, а не на сообщения.
7. **Лёгкий аудит-лог** недавно удалённых модерацией сообщений (`!falsepositives`), чтобы админам было проще подбирать пороги.
8. Стоит иметь в виду, что репутация в текущей схеме уже общая для всех групп бота (`Member.user_id` уникален глобально) — это можно и дальше использовать как плюс, а не только как особенность схемы.
9. **Экономика на репутацию** («покормить Шишку», открывать редкие фото за очки) и достижения/бейджи — обсуждались как идея геймификации, пока не реализованы.
10. **Метрики в формате Prometheus** вместо простого JSON на `/metrics` — если понадобится готовый дашборд в Grafana.

Если что-то из списка нужно в первую очередь — дайте знать, и это можно реализовать отдельным PR.
