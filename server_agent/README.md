# Агент сервера (панель владельца)

Маленький HTTP-сервис на хосте VPS. Через него бот управляет тем, что живёт вне его контейнера:

- **AmneziaWG** (нативно, `/root/awg/manage_amneziawg.sh`): список клиентов, статистика, выпуск и отзыв ключей, выдача `.conf`, `vpn://` и QR;
- **MTProto-прокси** (контейнер `mtproto-proxy`): статус, перезапуск, ссылка;
- **сервер**: аптайм, нагрузка, память, диск, контейнеры.

Только стандартная библиотека Python 3.10+, ставить ничего не нужно.

## Безопасность

- Слушает `172.17.0.1:8765` (интерфейс `docker0`). Из интернета недоступен, бот ходит через `host.docker.internal`.
- Каждый запрос проверяется по токену (`Authorization: Bearer …`, сравнение за постоянное время).
- Только белый список действий. Shell не используется, имена клиентов и сроки проверяются регуляркой, а имя не может начинаться с `-`.
- В боте панель видна только владельцу (`BOT_OWNER`) и только в личке. Отзыв ключа и перезапуск прокси требуют подтверждения.

Если бота взломают, злоумышленник сможет выпускать и отзывать VPN-ключи и перезапускать прокси. Ни на что другое на хосте токен агента прав не даёт.

## Установка / обновление

На сервере, из папки бота:

```bash
cd /root/shishka-bot && git pull
bash server_agent/install.sh <публичный-IP-или-домен>
docker compose up -d --build
```

`install.sh` копирует агента в `/opt/shishka-agent`, ставит systemd-юнит `shishka-agent` и создаёт `/etc/shishka-agent.env` со случайным токеном. Тот же токен он прописывает в `.env` бота (`SERVER_AGENT_URL`, `SERVER_AGENT_TOKEN`). При повторном запуске токен не меняется.

Если включён UFW, нужно разрешить трафик из сетей Docker к порту агента:

```bash
ufw allow from 172.16.0.0/12 to 172.17.0.1 port 8765 proto tcp
```

Проверка: `curl -s -H "Authorization: Bearer $(sed -n 's/^AGENT_TOKEN=//p' /etc/shishka-agent.env)" http://172.17.0.1:8765/health`

Логи: `journalctl -u shishka-agent -f`

## В боте (личка, только владелец)

| Команда | Что делает |
|---|---|
| `!server` / `!сервер` | панель с кнопками: статус, VPN-ключи, прокси |
| `!vpn_add имя [срок]` | выпустить ключ; срок `12h`, `7d`, `4w` (истёкшие ключи удаляет cron скрипта AWG) |
| `!vpn_del имя` | отозвать ключ (с подтверждением) |
