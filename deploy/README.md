# Переезд на другой сервер

Два скрипта: `backup.sh` собирает всё в один архив на старом сервере, `bootstrap.sh` разворачивает этот архив на новом.

## Что переносится

| Что | Как |
|---|---|
| AmneziaWG | `manage_amneziawg.sh backup` (конфиги, ключи сервера и клиентов, сроки), `awg0.conf`, настройки установки и сам установщик той же версии |
| MTProto-прокси | образ, порт и **тот же секрет**: достаются из `docker inspect mtproto-proxy` |
| Бот | `.env` (токен), `config.toml`, `data/` (база), модели `nsfw_model/` и `ruspam_model/` |
| Агент сервера | `/etc/shishka-agent.env` (токен остаётся прежним) |

## 1. Старый сервер

```bash
bash /root/shishka-bot/deploy/backup.sh --stop-bot
```

- `--stop-bot` останавливает бота перед копированием базы. Используйте при настоящем переезде, чтобы ничего не потерялось. Для пробного бэкапа запускайте без флага.
- `--no-models` не кладёт в архив модели (~700 МБ). Тогда новый сервер скачает их сам при первом старте.

Архив появится в `/root/shishka-backup-<дата>.tar.gz` с правами 600. **В нём все секреты**, никуда его не выкладывайте.

## 2. Новый сервер (чистая Ubuntu 22.04/24.04, root)

```bash
scp /root/shishka-backup-*.tar.gz root@НОВЫЙ_IP:/root/     # со старого сервера
ssh root@НОВЫЙ_IP
curl -fsSL https://raw.githubusercontent.com/Luno-o/shishka_bot/master/deploy/bootstrap.sh -o bootstrap.sh
bash bootstrap.sh /root/shishka-backup-<дата>.tar.gz
```

Скрипт ставит Docker, AmneziaWG, прокси, бота и агента. AmneziaWG требует двух перезагрузок (модуль ядра через DKMS): **сервер перезагрузится сам и продолжит после старта**. SSH-сессия при этом оборвётся, это нормально. Следить за ходом установки: `tail -f /var/log/shishka-bootstrap.log`. В конце скрипт выведет проверку сервисов и новую ссылку на прокси.

Если IP не определился автоматически или нужен домен, укажите `--host=IP_или_домен`. Повторный запуск безопасен: уже выполненные шаги пропускаются.

## 3. После переезда

1. На старом сервере бот должен быть остановлен: два бота с одним токеном мешают друг другу.
2. **VPN:** ключи клиентов прежние, но адрес сервера сменился. Разошлите новые конфиги: в боте `!server` → VPN-ключи → клиент → «Для Amnezia».
3. **Прокси:** секрет прежний, но в ссылке новый IP. Ссылку можно взять в `!server` → Прокси → Ссылка.
4. Если в DNS есть записи, указывающие на старый IP, обновите их.
5. Удалите `/root/shishka-restore`: там распакованные секреты.

Совет: чтобы при следующем переезде клиентам не пришлось менять конфиги, заведите домен для сервера и запустите bootstrap с `--host=домен`. Тогда при смене сервера достаточно будет поменять запись в DNS.
